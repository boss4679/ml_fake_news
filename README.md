# 📰 News Article Classification with Machine Learning

A machine learning pipeline that classifies news articles as **Reliable** or
**Unreliable** using **logistic regression** over **TF-IDF** features, with
**BeautifulSoup** scraping for real-time classification straight from a URL.

## What it does

- **TF-IDF vectorization** turns article text into features (unigrams + bigrams,
  English stop-words removed, sublinear term frequency).
- A **logistic regression** classifier is trained on labeled *true* and *fake*
  news articles.
- **BeautifulSoup** scrapes the main body text from any news URL so you can
  classify live articles.
- Ships with a **CLI**, a small **Flask web app**, and a **Chrome extension**
  that classifies pages live as you browse — entirely in the browser, no server.

Label convention: **1 = Reliable, 0 = Unreliable.**

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Train

```bash
python -m src.train
```

This loads the dataset, fits the pipeline, prints a classification report and
confusion matrix, and saves the model to `models/news_classifier.joblib`.

### Using the full public dataset

The bundled `sample_news.csv` is only for a quick demo. For real accuracy, use
the Kaggle **"Fake and Real News"** dataset:

1. Download `True.csv` and `Fake.csv`.
2. Drop both into the `data/` directory.
3. Re-run `python -m src.train` — they are detected automatically.

You can also supply your own single `data/news.csv` with `text` and `label`
columns (`label` may be `reliable`/`unreliable`, `real`/`fake`, or `1`/`0`).

## Classify

**From raw text:**

```bash
python -m src.classify --text "Breaking: scientists discover a miracle cure..."
```

**From a URL (scraped with BeautifulSoup):**

```bash
python -m src.classify --url https://www.example.com/some-news-story
```

**In Python:**

```python
from src.classify import Classifier

clf = Classifier()
print(clf.classify_text("Some article text..."))
print(clf.classify_url("https://example.com/story"))
```

## Chrome extension (live, in-browser)

The extension classifies pages **as you read them**, with no backend — the model
runs entirely in your browser, so nothing you visit is sent anywhere.

### Why this works without a server

The trained model is *linear* (TF-IDF features → logistic regression), so it is
nothing but a vocabulary, per-term IDF weights, and per-term coefficients. Those
export to a JSON file, and `extension/classifier.js` reproduces scikit-learn's
math in ~100 lines of JavaScript. No TensorFlow.js, no ONNX, no runtime.

`tests/` proves the JS classifier matches the Python model to floating-point
precision (max difference ~1e-16):

```bash
python -m tests.gen_expected     # Python predictions -> tests/expected.json
node tests/parity_test.mjs       # assert JS matches within 1e-6
```

### Build and load it

```bash
# 1. Train (if you haven't) and export the model for the browser:
python -m src.train
python -m src.export_model        # writes extension/model.json

# 2. Load it into Chrome:
#    - open chrome://extensions
#    - enable "Developer mode" (top-right)
#    - click "Load unpacked" and select the `extension/` folder
```

Now browse to any news article. The toolbar badge shows the confidence and a
color (green = Reliable, red = Unreliable); click the icon for details.

### How the pieces fit

1. `content.js` runs on each page, uses Mozilla **Readability** to pull the main
   article text, and messages it to the background worker.
2. `background.js` loads `model.json` once, runs `classifier.js`, paints the
   toolbar badge, and caches the result for the popup.
3. `classifier.js` mirrors `preprocess.clean_text` + TF-IDF + logistic
   regression exactly, so browser predictions equal the Python ones.

Whenever you retrain, re-run `python -m src.export_model` and reload the
extension to pick up the new model.

## How it works

1. `preprocess.clean_text` lowercases text and strips URLs, emails, digits and
   punctuation. The same function is wired into the TF-IDF vectorizer, so
   training and inference always transform text identically.
2. `TfidfVectorizer` builds the feature matrix; `LogisticRegression`
   (`class_weight="balanced"`) learns the decision boundary.
3. The fitted `Pipeline` is serialized with `joblib` and reloaded for inference.
4. For URLs, `scraper.scrape_article` fetches the page, removes non-content tags
   (scripts, nav, footers…), and joins the paragraph text before classifying.

## What the model learned (and its limitations)

Because the model is linear, every term has one coefficient, so you can read off
exactly what drives its decisions:

```bash
python -m src.inspect_model --top 12
```

On the Kaggle dataset this reveals an honest and instructive problem — **data
leakage**:

```
Top terms → RELIABLE:     reuters (+37.3), said, washington reuters, president donald, ...
Top terms → UNRELIABLE:   video (-14.6), read, featured image, watch, breaking, ...
```

Every "real" article in this dataset is a Reuters wire story, so the model
largely learned *"does this look like a Reuters article?"* rather than a general
notion of reliability. The "unreliable" signals are similarly the formatting
quirks of the specific fake-news sites in the data (`featured image`, `watch`,
`video`).

**Takeaways this project demonstrates:**

- The reported ~99% accuracy reflects the dataset's source imbalance, not
  real-world misinformation detection. A trustworthy evaluation would use
  **source-balanced** or cross-source data (train on some outlets, test on
  others), where accuracy drops substantially.
- The model detects *writing style and provenance*, not truth. It is **not** a
  fact-checker. Treat every prediction as a weak signal, never a verdict.
- Coefficient inspection is the cheapest, most valuable diagnostic a linear text
  model offers — and the reason a simple, interpretable model was chosen here.
